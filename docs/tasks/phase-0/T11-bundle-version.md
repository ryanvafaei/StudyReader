## Goal
XcodeGen hardcodes `CFBundleShortVersionString` to `1.0` and `CFBundleVersion` to `1` in the generated Info.plist, so `MARKETING_VERSION` (0.1.0) and `CURRENT_PROJECT_VERSION` never reach the bundle. Make the bundle read them from the build settings.

## Files to touch
- `project.yml` (add two keys under the app target's `info.properties`)
- `StudyReader/Resources/Info.plist` (regenerated by `xcodegen generate`; commit the result)
- `StudyReaderTests/AppTests/BundleVersionTests.swift` (new)

## Change
In `project.yml`, under the StudyReader target's `info.properties`, add:
```yaml
CFBundleShortVersionString: "$(MARKETING_VERSION)"
CFBundleVersion: "$(CURRENT_PROJECT_VERSION)"
```
Then run `xcodegen generate` (no cache) so `Info.plist` is regenerated. Do not hand-edit the plist or touch the `.xcodeproj`. If `CURRENT_PROJECT_VERSION` is not set in `Config/Base.xcconfig` or `project.yml`, report it instead of inventing a value.

## Tests
`BundleVersionTests/versionComesFromBuildSettings`: load `Bundle.main.infoDictionary` (the app is the test host) and assert `CFBundleShortVersionString == "0.1.0"` and that `CFBundleVersion` is a non-empty string that is not the literal `"$(CURRENT_PROJECT_VERSION)"`.

## Acceptance criteria
1. Generated `Info.plist` contains `$(MARKETING_VERSION)` and `$(CURRENT_PROJECT_VERSION)` for the two keys. → inspect the file
2. The built app reports version 0.1.0. → `BundleVersionTests/versionComesFromBuildSettings`
3. Full suite passes with no new warnings.

## Out of scope
Anything else in `project.yml`, signing, entitlements.
