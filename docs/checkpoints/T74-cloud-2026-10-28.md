## Spec FAILs (only these become fix tasks)

1. **T72, Open With / opening files from Finder no longer imports (SPEC F-02). Three tests fail:**
   - `ExternalOpenTests/testDuplicateOpenWithStillShowsTheSummaryAlert`: `ExternalOpenTests.swift:67` "The first open didn't import the file."
   - `ExternalOpenTests/testOpenWithWhenNotRunningLaunchesOnceAndImports`: `ExternalOpenTests.swift:99` "The launched app didn't import the file."
   - `ExternalOpenTests/testOpenWithWhileRunningImportsIntoTheRunningInstance`: `ExternalOpenTests.swift:52` "The running instance didn't import the file. Tabs: ["Library", "Sample · Lecture 1: Cell Biology"], instances: 1"

   All three passed at T69 (run 40610848003, 15 to 22 s each). The test encodes spec behaviour (T48/T52j: a file opened with `NSWorkspace` reaches the running or newly launched instance and imports with no alert), so this is a **SPEC FAIL, not a test bug and not a launch flake**: it fails in all three variants (running with a reader open, running with the library only, cold start), the app launched fine (one instance, 1 process), and the hierarchy dumps (`B583DAA6-9F27-4FAE-8CAE-93275858F2F3.txt`, `F68A1531-94E6-46F1-B42B-C33D48F63F49.txt`, `EA150D92-34DB-497A-AD78-FBCAAAC5A132.txt`) show a normal library with the 9 seeded cards and no card for the opened file, no import alert and no spinner. The file URL simply never reached the import path.

   Likely cause (unverified, no Mac here and I did not edit code): T72 added a SwiftUI `.onOpenURL` modifier to the main window, `StudyReader/App/StudyReaderApp.swift:16-21`, which ignores file URLs (`if !url.isFileURL { GoogleSignInAuth.handle(url) }`). It is the only `.onOpenURL` in the app, and it was added between the last green run and this one (`git diff 92ac5df 8b2c6a7`). With `.onOpenURL` present SwiftUI handles the open-URL Apple event itself, so `AppDelegate.application(_:open:)` (`AppDelegate.swift:8-18`, which forwards file URLs to `ExternalURLRouter.shared.receive`) is probably no longer called, and the modifier then drops the file. The T72 change to `AppDelegate` (splitting file and non-file URLs) is harmless by itself. Suggested fix for a small task: route file URLs inside `.onOpenURL` to `ExternalURLRouter.shared.receive([url])` (or remove the modifier and keep the Google redirect in `AppDelegate`, which already handles non-file URLs), then re-run only `./scripts/ci.sh uitest StudyReaderUITests/ExternalOpenTests` (3 tests, about 2 minutes). Also check on the Mac that Google's sign-in redirect still returns to the app after the fix (T72 Needs-a-Mac row).

   Impact: Finder Open With, Dock-icon drops and "open file" no longer import. This is the primary way to get files in besides drag-and-drop and File > Import, so I treat it as high priority.

No other spec FAILs found. The T69 layout FAIL is fixed (below).
