1. **Seeded highlights show no text in the side panel (and in the popover).** Debug > Seed Sample Library inserts highlights without `richText` (`SampleLibrary.swift` `highlight(for:in:now:)`, both `Highlight(...)` initialisers at about lines 228 and 257; `richText` defaults to `""`, `Highlight.swift:13`). `HighlightsPanelView.swift:122` shows `row.highlight.richText` (and `HighlightPopoverView.swift:78` does the same), so the three rows of the Lecture PDF show only the colour bar, the note and "p. So this is a defect in the Debug seed, but SPEC F-06 ("text excerpt") and the whole T62/T63 Mac checklist ("text (3 lines)", popover text, Copy) can't be verified on the seed library until it's fixed. Fix: seed `richText` (for example `RichTextMarkdown.escape(text)`), and consider falling back to `text` when `richText` is empty. Repro: seed, open the Lecture PDF, open the panel (⌥⌘I).

2. **Candidate, NOT confirmed: seeded Markdown highlights aren't drawn.** Screenshot `A9351ED0-71F0-4B60-AD1D-579CE6B3572A.png` ("Reader subtitle after category deletion") shows "Sample · Notes: Gradient Descent" in its tab, at least 10 s after it was opened, with the text fully rendered and no coloured band on any of the four seeded phrases ("lowers the loss", "too large a step can diverge", "small batch of examples", "running average"). Possible causes: a race between `loadIfNeeded()` / `highlightsChanged()` / re-anchoring in `MarkdownReaderView.swift` (see backlog B12), or highlights not drawing while the tab was in the background. I can't tell from one screenshot. **Settle it with one cheap CI test** (item C1 below: open Gradient Descent, wait 3 s, pixel-check for the yellow band, and count the panel rows). If the band is missing with the tab in front, it is a T60 spec FAIL (F-06 AC3/AC4).

## Observations (not spec failures; for docs/BACKLOG.md)

- **OB1 (test isolation):** the highlight colour persists between UI-test launches: the toolbar button is yellow in the first PDF screenshots and pink in the later ones (after `testHighlightColorMenu…` chose "Question"). Settings are not in memory. New highlight tests must set the colour first (via the menu), or they depend on test order. Same for any auto-highlight setting a test changes.
- **OB2 (page contrast):** at fit width the PDF page is full-bleed white against a white reader background with the panel closed (`6020CF9F…png`); page edges show only as a faint shadow and a thin gap. With the panel open the surrounding background is light grey and the page reads better. Consider a slightly grey reader background.
- **OB3 (loading chrome):** while the Markdown reader loads (`B179664D…png`) the toolbar items are hidden and the title is single-line ("…Gradient Descent – Notes"), then the toolbar pops in and the title becomes two lines. A brief layout change on open; harmless. It also means the "Step 3" screenshot doesn't show a loaded document (the test doesn't wait for content).
- **OB4 (seed):** `Sample · Notes: Gradient Descent` highlights are anchored with offsets computed in the source text (paragraphs joined by a blank line); the rendered text may use different separators. If Spec FAIL 2 turns out to be an anchoring issue, re-anchoring of seeded anchors is the place to look (B10, B12).
- **OB5 (a11y, B16-2):** the side-panel rows combine their children and set the label "Highlight", which replaces the row text for VoiceOver and for XCUITest. Tests can count rows but not read excerpts. Use the highlight text as the label (backlog B16-2); then C2 to C7 can assert on text.
- **OB6 (CI coverage gap):** no suite exercises any reader content (see Coverage). The existing helper `StudyReaderUI` has no reader-content queries yet (page field, panel rows, popover).
