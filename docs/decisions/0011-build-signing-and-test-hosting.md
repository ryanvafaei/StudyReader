# ADR-0011: Build settings, signing, and hosted tests

- Status: Accepted
- Date: 2026-10-23

## Context
Agents build and test from the command line without the user's Apple team ID. ARCHITECTURE §2.2 lists a `keychain-access-groups` entitlement for GoogleSignIn; on macOS that is a restricted entitlement that needs a provisioning profile (team), so including it in Phase 0 would break unsigned builds and test launches. Hosted unit tests also launch the real app, and `.xcodeproj` (where Xcode writes `Package.resolved`) is git-ignored.

## Decision
- `Info.plist` and `StudyReader.entitlements` are generated by XcodeGen from `info.properties` / `entitlements.properties` in `project.yml`. Commit the generated files; never hand-edit them.
- Phase 0 signs ad hoc: `CODE_SIGN_IDENTITY = "-"`, `DEVELOPMENT_TEAM = ""`. Entitlements: app sandbox, user-selected read-only, network client. `keychain-access-groups` and the team ID are added by the Google sign-in task in Phase 1 (E1.8), which is the first code that needs them.
  - Amended 2026-10-24: the user's Apple team ID is **`597KGSTZWJ`**. Phases 0–1 stay ad-hoc signed. `DEVELOPMENT_TEAM` is **not** set until E1.8; the E1.8 sign-in task sets `DEVELOPMENT_TEAM: 597KGSTZWJ` in `project.yml` together with `keychain-access-groups`, and no earlier task touches it.
- Swift 6 language mode, strict concurrency complete. Default actor isolation stays **nonisolated** (do not set `SWIFT_DEFAULT_ACTOR_ISOLATION` or approachable-concurrency flags); UI models are explicitly `@MainActor`.
- Debug config sets `DEAD_CODE_STRIPPING = NO` so hosted tests can link package symbols the app doesn't use yet. Packages are linked only into the app target, never also into the test target (that would duplicate them); tests `import GRDB` / `import Markdown` through the host.
- Test fixtures: `StudyReaderTests/Fixtures` is a folder reference copied into the test bundle; look files up with `Bundle(for:)` and subdirectory `Fixtures/<kind>`.
- `.gitignore` ignores everything in `StudyReader.xcodeproj/` except `project.xcworkspace/xcshareddata/swiftpm/Package.resolved`, which is committed.
- When the app runs as a test host (`XCTestConfigurationFilePath` or `XCTestBundlePath` in the environment) it uses an in-memory database and a temporary FileStore, never the user's library.
  - Amended 2026-10-24 (bug hunt M4). The launch argument `-StudyReaderInMemory` forces the same in-memory environment, for example for UI tests (XCUITest sets `launchArguments`) or manual runs. ~~The decision goes through `AppEnvironment.usesInMemoryLibrary()`.~~ Since T27 it goes through `AppEnvironment.TestHostSignals.usesInMemoryLibrary` (see below).
  - ~~`AppEnvironmentTests/hostedProcessIsDetected` checks detection against the real process environment, so a renamed Xcode variable fails a test instead of opening the real library.~~ Reworded 2026-10-24 (second bug hunt L1): that was wrong. The host decides at launch, before any test runs, so with one signal a renamed variable opened and migrated the real library first and the test only reported it afterwards.
  - Amended 2026-10-24 (second bug hunt L1, T27). The choice is made from three independent signals, read once in `StudyReaderApp.init()` (`AppEnvironment.launchTestHostSignals`) before anything opens a library: (1) Xcode's XCTest environment variables; (2) `STUDYREADER_IN_MEMORY`, set by the `project.yml` test action (`shouldUseLaunchSchemeArgsEnv: false`), or the launch argument `-StudyReaderInMemory`; (3) an XCTest library that Xcode injected into the process (dyld image name starting with `XCTest`/`libXCTest`). Any one selects the in-memory library; `AppLaunchModel.chooseEnvironment` calls `live()` only when all three are absent. Each signal has its own guard test against the real process. Guarantee: one or two broken signals fail a test and the real library stays closed. If all three break at once, the real library is opened and the tests only report it afterwards. The run action must never set the variable or argument.
  - Amended 2026-10-24 (Phase 1 planning, backlog T27-F1, task T31): a fourth signal, Xcode Previews (`XCODE_RUNNING_FOR_PREVIEWS` equal to `1`), also selects the in-memory library. Whether a preview process runs `live()` is unverified, so previews are guarded instead of checked.
  - Temporary libraries go under `tmp/StudyReader-InMemory/`. Folders older than one hour are removed when `inMemory()` runs. Tests remove their own folders with `TestFileStore.remove(_:)` (T14).

## Alternatives considered
Require the team ID in Phase 0 (blocks agents); separate entitlements files switched by xcconfig (more moving parts before they're needed); move app logic into a framework target so tests needn't be hosted (re-decides ARCHITECTURE §2). For the L1 signals (2026-10-24): `Bundle.allBundles` containing a `.xctest` bundle or `NSClassFromString("XCTestCase")` were rejected, because they only turn true once the test bundle loads, which can be after the launch decision; the bundle path can't tell a test host from an Xcode Run, since both start from DerivedData.

## Consequences
Phase 0–1 builds run anywhere (ad hoc). The team ID for E1.8 is known (`597KGSTZWJ`), so E1.8 isn't blocked on it. Rebuilt ad-hoc apps may trigger a macOS "access data from other apps" prompt for the container; accept it during development.
