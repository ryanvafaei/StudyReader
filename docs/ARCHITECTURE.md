## 1. Overview

```

│ Library · Reader chrome · Highlights browser · Review · Settings             │
│        @Observable feature models  ←── GRDB ValueObservation (live lists)    │
├──────────────────────────── Reader engines (AppKit) ─────────────────────────┤

│ highlight annotations, snapshot      highlight rendering attrs, paged mode   │

│ ExportRenderer · GoogleExportService · EmbeddingService · SuggestionService  │
├──────────────────────────── Core ────────────────────────────────────────────┤
│ AppDatabase (GRDB DatabasePool, migrations, FTS5) · Repositories · Models    │

└──────────────────────────────────────────────────────────────────────────────┘
External: Google Drive API (export only) · Apple NaturalLanguage · FoundationModels
```

Rules:
- Views never talk to GRDB or services directly; they go through `@Observable` feature models.
- Services contain the logic and are unit-tested without UI.
- Only `GoogleExportService` touches the network.

## 3. Concurrency model

- Swift 6 language mode, strict concurrency complete.
- `AppDatabase` wraps a GRDB `DatabasePool` (WAL). It is `Sendable` and created once in `AppEnvironment`.
- Repositories are `Sendable` structs holding a `DatabaseWriter`; all methods are `async` (`try await writer.write { … }` / `read`).
- UI models are `@MainActor @Observable` classes. Live lists use GRDB `ValueObservation` started in `.task {}` and cancelled with the view.
- Long work runs in actors: `ImportService`, `ExtractionService`, `EmbeddingService`, `GoogleExportService`.
- **PDFKit is not thread-safe.** Background work (extraction, cover, snapshot rendering) opens its *own* `PDFDocument(url:)` instance; never pass a `PDFDocument`/`PDFPage` across actors. The UI's `PDFView` document lives on the main actor.
- Time comes from an injected `Now` (`protocol Now: Sendable { func callAsFunction() -> Date }`), never `Date()` in logic. `SystemNow` returns `Date.storageRounded` values (1/1024 s grid), so stored dates are `==` after a round trip (ADR-0012).
- The library opens off the main actor: `AppLaunchModel.start()` is `async` and runs the environment factory in a detached task.

## 4. Data model (SQLite via GRDB, migrations `v1` and `v2`)

IDs are `TEXT` UUIDs (canonical uppercase, `UUID().uuidString`). Dates are `REAL` (Unix seconds). JSON columns hold `Codable` structs. Coding rules: ADR-0012. SQL table names below stay as written. Only the Swift types are renamed, to avoid clashes with Markdown, ObjectiveC, Testing, FSRS and SwiftUI.

| SQL table | Swift record type |
|---|---|
| `category` | `DocumentCategory` |
| `document` | `LibraryDocument` |
| `documentText` | `DocumentText` |
| `highlight` | `Highlight` |
| `tag` | `LibraryTag` |
| `highlightTag` | `HighlightTag` |
| `documentTag` | `DocumentTag` |
| `documentNote` | `DocumentNote` |
| `reviewCard` | `ReviewCard` |
| `reviewLog` | `ReviewLogEntry` |

Full-text search uses FTS5 external-content tables with tokenizer `studyreader` (ADR-0014). `studyreader` is a GRDB wrapper around `unicode61 remove_diacritics 2` that keeps the soft hyphen (U+00AD) inside words, then normalizes each token: NFKC (unfolds ligatures such as ﬁ), remove soft hyphens, lowercase. It is English-only; Persian/Arabic folding was deliberately left out and would need a new tokenizer version and migration. The tokenizer is registered on every connection in `AppDatabase.makeConfiguration()`. Since `v2`, hand-written triggers `<fts>_ai`, `<fts>_ad` and `<fts>_au` keep the tables in sync. The update trigger fires only `AFTER UPDATE OF` the indexed columns (ADR-0013). `v1` created these tables with `unicode61` and GRDB `synchronize(withTable:)` triggers, and `v2` dropped and rebuilt them.
- `documentText_fts(text)` ← `documentText`
- `highlight_fts(text, editedText, note)` ← `highlight`
- `documentNote_fts(body)` ← `documentNote`
- `document_fts(title, author)` ← `document`

Migration rules (ADR-0013):
- Migrations are append-only. A migration is frozen once its task is committed: `v1` (`SchemaV1`) and `v2` (`SchemaV2`) are frozen.
- Each migration `vN` has a schema golden `StudyReaderTests/Fixtures/schema/vN.sql`, checked by `SchemaSnapshotTests`.
- Each later change is a new named migration, with a test that upgrades the populated `V1FixtureDatabase`.

## 5. Highlight anchoring

`HighlightAnchor` is a `Codable` enum stored as JSON in `highlight.anchor`. It was named `Anchor` before T13, and the JSON is unchanged:

```swift
enum HighlightAnchor: Codable, Sendable, Equatable {
  case pdf(PDFAnchor)        // view == .pdf, kind == .text
  case text(TextAnchor)      // view == .text (PDF text view) or .markdown
  case image(ImageAnchor)    // kind == .image
}
struct PDFAnchor: Codable, Sendable, Equatable {
  struct PageRects: Codable, Sendable, Equatable { var pageIndex: Int; var rects: [CGRectCodable] }
  var pages: [PageRects]     // one entry per page touched, in order
  var text: String           // selected text
  var prefix: String         // up to 32 chars before
  var suffix: String         // up to 32 chars after
}
struct TextAnchor: Codable, Sendable, Equatable {
  var start: Int             // UTF-16 offset into the joined text (§6) or rendered Markdown string
  var length: Int            // UTF-16 length
  var text: String
  var prefix: String         // up to 32 chars
  var suffix: String
  var sourceVersion: Int     // extractionVersion (PDF) or MarkdownRenderer.version
}
struct ImageAnchor: Codable, Sendable, Equatable { var pageIndex: Int; var rect: CGRectCodable }
```

### 5.1 PDF view
- Rects are in **PDF page space** (points, origin bottom-left of the page's crop box), one rect per selected line: `selection.selectionsByLine()` → `lineSelection.bounds(for: page)`.
- Cross-page selections: iterate `selection.pages`; each page gets its own `PageRects`.
- Zoom, resize, and display-mode changes don't affect page-space rects, so no conversion is stored.
- Rendering: on document open, for each highlight and each page entry, add an in-memory `StudyHighlightAnnotation` (subclass of `PDFAnnotation`, subtype `.highlight`) with `bounds` = union of rects and `quadrilateralPoints` = each rect's 4 corners **relative to `bounds.origin`** (PDFKit expects annotation-relative quads; see `.references/YoPDF/macos/YoPDFCore/HighlightService.swift` for the same pitfall). Store the highlight ID on the annotation.
- Never call `PDFDocument.write`. Annotations are display-only; the database is the source of truth.
- Hit testing: `page.annotation(at:)` → highlight ID → popover.

### 5.2 Text view and Markdown
- The text is shown in `TextReaderView` (NSTextView with TextKit 2, non-editable, selectable). Offsets are **UTF-16** (`NSRange`), matching NSTextView.
- Rendering: `NSTextLayoutManager.addRenderingAttribute(.backgroundColor, …, for: textRange)`. Rendering attributes don't change the text storage, so offsets stay stable.
- Hit testing: character index at click point → topmost highlight containing it.

### 5.3 Re-anchoring (text and Markdown)
When opening a document whose `sourceVersion` differs from the anchor's, or when the text at `[start, start+length)` doesn't equal `text`:
1. Search for `text` within ±2,000 UTF-16 units of `start`; if several matches, pick the one whose surrounding text best matches `prefix`/`suffix`.
2. Otherwise search the whole text with the same scoring.
3. If found: update `start`, `sourceVersion`, save.
4. If not found: set `anchorStatus = 'orphaned'`. Orphaned highlights stay in lists and review, show "Couldn't locate in document", and aren't drawn.

PDF-view anchors don't need re-anchoring (page-space geometry is stable for an unchanged file; files never change after import).

### 5.4 Image highlights
- `SnapshotService` (background actor, own `PDFDocument`) renders `page` cropped to `rect` at 2× via `PDFPage.draw(with:to:)` into a CGContext → PNG at `Documents/<doc>/snapshots/<highlight-id>.png`.
- Always uninverted (rendered from the page, not from the screen).

### 5.5 Reading order (`positionKey`)
- PDF view / image: `Double(pageIndex) * 1_000_000 + (pageHeight - topOfFirstRect)`
- Text / Markdown: `Double(start)`
Panels sort by `positionKey`; PDF-view and text-view highlights of the same document are listed in one panel, each sorted within its group.

## 6. PDF text extraction (text view + search)

`PDFTextExtractor` (pure function over a background-owned `PDFDocument`), versioned by `PDFTextExtractor.version` (stored in `document.extractionVersion`; bumping it re-extracts on next launch).

Per page:
1. `page.attributedString` (fall back to `page.string`). Normalize line endings to `\n`, collapse runs of spaces/tabs, NFC-normalize.
2. Lines = split by `\n`, trimmed.
3. Bullet lines (start with •, ▪, ◦, –, -, *, or `\d+[.)]`) start a new paragraph, prefixed `• ` (numbers kept).

Across pages:
4. **Repeated headers/footers:** among the first 2 and last 2 lines of each page, a line whose digit-normalized form (digits → `#`) appears on ≥ 50% of pages (min 3 pages) is removed everywhere. Lone page-number lines are removed.

Paragraph joining within a page:
5. Line ending in `-` and next line starting lowercase → join without the hyphen.
6. Line not ending in `.?!:;` and next line starting lowercase → join with a space.
7. Otherwise → paragraph break (`\n\n`).

Output:
8. Each page becomes one `documentText` row (`unitIndex` = page index). The text view shows `join(pageTexts, separator: "\n\n")`; `startOffset` = UTF-16 offset of the page in that joined string. The text view draws "Page N" separators as non-text decorations (not part of the string).
9. Bold/italic/monospace runs from the attributed string are stored in `runs` (offsets relative to the page text) for rich-text highlights in text view (SPEC F-07).

Accepted limitations: math, tables, and multi-column slides may reflow imperfectly. A later optional improvement is Vision `RecognizeDocumentsRequest` (macOS 26+) for pages where extraction looks poor (ADR-0009); not in v1 scope unless the user asks.

Markdown documents: `documentText` rows are filled from the rendered plain string (one row per top-level heading section) for search; text anchors use offsets into the rendered string (`MarkdownRenderer.version`).

## 7. Markdown rendering

`MarkdownRenderer` walks a swift-markdown `Document` (`MarkupWalker`) and produces:
- `NSAttributedString` with semantic fonts (based on appearance settings), paragraph styles, list markers, table layout via tab stops (simple grid), code-block background via a custom attribute drawn by the text view, image attachments (`NSTextAttachment`) from copied local images or placeholders.
- `SourceMap`: sorted list of `(renderedRange: NSRange, node: inline kind + formatting)` used to build rich text (SPEC F-07) for a selected range.
- `version: Int` constant; bump when output text changes (triggers re-anchoring, §5.3).

Front matter is stripped before parsing; `title`/`author` returned separately.

## 8. Search

- `SearchQueryParser` converts user input to an FTS5 MATCH expression: bare words → `"word"` (AND-joined); `word*` → `"word"*`; `"exact phrase"` kept; `-word` → `NOT "word"`. All user text is quoted/escaped; never interpolate raw input.
- The parser does no Unicode normalization. FTS5 runs MATCH strings through the `studyreader` tokenizer, so `photosynthesis` matches `photo\u{00AD}synthesis` (soft hyphen), `find` matches `ﬁnd` (ligature), and `cafe` matches `Café` (ADR-0014). `snippet()` returns the original stored text.
- `SearchService.search(query, filters, limit)` runs four FTS queries (documentText, highlight, documentNote, document), each with `bm25()` ranking and `snippet(…, '**', '**', '…', 12)`, joins to apply filters (tag, category, file type), and returns grouped results with locations:
  - documentText hit → (documentId, pageIndex / unitIndex)
  - highlight hit → (documentId, highlightId)
  - note hit → (documentId, highlightId?) 
- Opening a page hit in PDF view: `PDFDocument.findString(_:withOptions:)` limited to that page to select the first match.
- In-document find uses PDFKit find (PDF view) or NSTextView find bar (text/Markdown).

## 9. Export (Google Docs)

### 9.1 Rendering (`ExportRenderer`, pure, golden-file tested)

Markdown, grouped by document (default):

```markdown
# StudyReader – {scope name}

_Exported {yyyy-MM-dd HH:mm} · {N} highlights from {M} documents_

## {Document title}

_{Author} · {Category}_

### Document note

{document note body}

### Highlights

- **{Color label}** · p. {page}
  {rich text, rendered as Markdown}
  - Note: {note}
  - Tags: #tag1 #tag2

- **{Color label}** · p. {page}
  [Image highlight]
  - Note: {note}
```

- Documents ordered by title; highlights by `positionKey`.
- Group-by-tag variant: `## #{tag}` sections, each highlight followed by `_— {Document title}, p. {page}_`. Untagged last under `## Untagged`.
- Omitted parts when options are off or fields are empty (no empty headings).
- `editedText` is exported instead of `text`/`richText` when present.

### 9.2 Upload (`GoogleExportService`, actor)

- Auth: GoogleSignIn (`GIDSignIn.sharedInstance`), scope `drive.file`. Get a fresh access token before each request (`currentUser.refreshTokensIfNeeded`).
- Create: `POST https://www.googleapis.com/upload/drive/v3/files?uploadType=multipart&fields=id,webViewLink`
  - metadata `{"name": title, "mimeType": "application/vnd.google-apps.document", "parents": [folderId]?}`
  - media part `Content-Type: text/markdown; charset=UTF-8`
- Update: `PATCH https://www.googleapis.com/upload/drive/v3/files/{fileId}?uploadType=multipart&fields=id,modifiedTime` with metadata `{"name": title}` and the new media. Drive replaces the whole Doc content on a converting update.
- Format check: on first export per account, `GET https://www.googleapis.com/drive/v3/about?fields=importFormats` and confirm `text/markdown` lists `application/vnd.google-apps.document`. If not, set the target's `format = 'html'` and upload HTML (swift-markdown `HTMLFormatter`) with `Content-Type: text/html`.
- Errors: 401 → refresh once then ask to sign in; 403/404 on update → mark "Doc missing or no access", offer "Create new Doc"; 429/5xx → exponential backoff 1s/4s/16s; offline (`URLError.notConnectedToInternet`) → status `queued`, retry on network path change (`NWPathMonitor`).
- Keep-in-sync: `ExportSyncScheduler` observes DB changes affecting a target's scope (GRDB `DatabaseRegionObservation`) and debounces 60 s per target.
- Never log tokens, auth codes, or document contents. Log status codes and target IDs only.

## 10. Review engine

### 10.1 Scheduling (`ReviewScheduler`, pure struct)
```swift
struct ReviewScheduler: Sendable {
  var weights: [Double] = FSRSDefaults.defaultWv6   // FSRS-6
  var enableFuzz = true                              // tests set false
  func schedule(card: FSRS.Card, rating: Rating, now: Date, retention: Double) throws -> (card: FSRS.Card, log: FSRS.ReviewLog)
}
```
- Builds `FSRS(parameters: .init(requestRetention: retention, w: weights, enableFuzz: enableFuzz, enableShortTerm: false))` and calls `next(card:now:grade:)`.
- `FrequencyPolicy.retention(card:category:)`: card override > category; low 0.80, normal 0.90, high 0.95; off → suspended (never scheduled).
- New cards: `FSRS.Card(due: now)` (public initializer; `FSRSDefaults.createEmptyCard` is internal) with `dueAt = now`.
- `Rating` cases in swift-fsrs: `.manual` (never used), `.again`, `.hard`, `.good`, `.easy`. Two-button mode maps Forgot → `.again`, Remembered → `.good`.

### 10.2 Session builders (pure, take `Now`)
- `DailyReviewBuilder`: due non-suspended cards (`dueAt ≤ now`) ordered by `dueAt` asc, limit `dailyLimit`; then new cards (`state == new`, `introducedAt == nil`) ordered by highlight `createdAt`, limit `newPerDay − introducedToday`. "Today" starts at 04:00 local.
- `ThemedReviewBuilder`: filter → candidate cards (non-suspended), order dueFirst (due asc, then `lastReview` asc) or random (seeded RNG injectable), limit `cardsPerSession`. Excludes cards already rated today in another session.
- `ThemedReviewSchedule.isDue(review, now)`: daily → last completed before today's 04:00; everyNDays → ≥ N days since; weekdays → today is a listed weekday and not completed today.

### 10.3 Mastery
- Creating cloze/Q&A cards inserts `reviewCard` rows (`cardType` cloze/qa) with fresh FSRS state and sets the passive card `suspended = 1, suspendedReason = 'mastery'`. Deleting the last Mastery card unsuspends the passive card.
- Cloze display: replace each range in the active cloze group with `[…]`; back shows full text with the ranges emphasized.

## 11. Similarity (`EmbeddingService`, actor)

- Language via `NLLanguageRecognizer` on `editedText ?? text` + note. Embedding via `NLEmbedding.sentenceEmbedding(for: language)`; if nil for that language, skip (highlight excluded from similarity).
- Store Float32 vectors with `modelId` = `"NLEmbedding.sentence.<lang>"` and `sourceHash`. Recompute when hash differs (on highlight edit/note edit; on launch for stale rows).
- `SimilarityService.similar(to:limit:threshold:)`: load vectors with the same `modelId` (cache in memory, invalidate on change), cosine similarity, exclude self, threshold 0.55, top 5.

## 12. Mastery suggestions (`SuggestionService`, Foundation Models)

- Gate: `SystemLanguageModel.default.availability == .available`; otherwise the UI hides the button.
- `@Generable struct MasterySuggestion { @Guide(description: "The highlight text with 1–3 key terms wrapped in {{ }}") var cloze: String; var question: String; var answer: String }`.
- Instructions: produce study cards from the passage; no facts not present in the passage; answer ≤ 2 sentences.
- Input: highlight text + note, truncated to 1,500 characters.
- Result goes to the Mastery editor as editable drafts; nothing is saved without user confirmation.
- Handle `LanguageModelError` (guardrail, context, unavailable) with a short message; never crash.

## 13. Files and storage

- Root: `FileManager.default.url(for: .applicationSupportDirectory, …)/StudyReader/` (inside the sandbox container).
- `StudyReader.sqlite` (+ `-wal`, `-shm`).
- `Documents/<document-id>/original.<ext>`, `cover.png`, `images/` (Markdown images), `snapshots/<highlight-id>.png`.
- `FileStore` owns all paths; nothing else builds file paths.
- `FileStore` path builders throw `FileStoreError` unless document and highlight IDs are canonical uppercase UUID strings and the file extension is 1–10 lowercase letters or digits. `url(forRelativePath:)` returns nil for any path that would leave `Documents/` (absolute paths, `..`, or a first component that isn't a canonical document ID). `documentFolderIds()` lists only canonical IDs, so the orphan sweep never touches other folders.
- On launch: remove `Documents/<id>` folders with no `document` row (interrupted imports), and documents with `extractionStatus = 'pending'` re-queue extraction.

## 14. Error handling and logging

- Domain errors are typed enums per service (`ImportError`, `ExportError`, …) with user-facing messages via `LocalizedError`.
- Opening the library throws `AppDatabaseError` (`folderUnavailable`, `cannotOpen`, `damaged`, `migrationFailed`). The launch screen shows only its `errorDescription` and `recoverySuggestion`, and a generic message for any other error. Raw `DatabaseError` text (which can contain SQL) is never shown to the user.
- Known and accepted for now: on open or migration failures, the system SQLite library's own `[logging]` output (in the Xcode console and unified log) can include the failing SQL and the database file path. It comes from the OS, not from our `Log`/`os.Logger` calls (see `docs/bugs/backlog.md`).
- UI shows errors as inline banners or alerts; background failures surface in the item's status (e.g., library item "Text extraction failed — Retry").
- `os.Logger(subsystem: Bundle.main.bundleIdentifier!, category: <feature>)`. No PII: never log highlight text, notes, file contents, tokens, or emails.

## 15. Testing strategy

- Swift Testing (`import Testing`) for all logic; tests mirror `Features/` folders.
- `AppDatabase.makeInMemory()` for repository/service tests.
- `PDFFixtureBuilder` (tests only) generates PDFs with Core Text into a `CGContext(consumer:mediaBox:)` PDF context: plain multi-page text, two-column layout, repeated header/footer + page numbers, bold/italic/monospace runs, hyphenated line ends, slide-like bullets. No binary PDFs committed except tiny ones if unavoidable.
- `StudyReaderTests/Fixtures/private/` (git-ignored): the user may drop real lecture PDFs here for manual and optional tests; tests depending on them are skipped when absent.
- Golden files for `ExportRenderer` in `Fixtures/golden/`.
- Schema goldens in `Fixtures/schema/vN.sql` (`SchemaSnapshot`). `V1FixtureDatabase` builds a populated v1 database for upgrade tests. `FTSIntegrity.check(db)` runs FTS5 `'integrity-check'` on all four FTS tables, and every test that writes indexed tables calls it at the end.
- Temporary FileStores and in-memory environments are removed by the test that made them (`defer { TestFileStore.remove(store) }`).
- Network: `GoogleExportService` takes a `HTTPClient` protocol; tests use a stub returning canned responses.
- Time: `FixedNow` for scheduling tests; `enableFuzz = false`.
- UI isn't snapshot-tested. Tasks that change visuals require a user visual check (see CLAUDE.md).
