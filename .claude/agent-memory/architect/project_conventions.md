Decided 2026-10-23/24 in Phase 0 and Phase 1 planning. Authoritative text: docs/decisions/0011–0018; module maps in docs/tasks/phase-0/README.md and docs/tasks/phase-1/README.md (incl. "Shared interfaces" table).

- Record names avoid module clashes: `LibraryDocument`, `DocumentCategory`, `LibraryTag`, `ReviewLogEntry`; others = table name UpperCamel. `HighlightAnchor` (file Anchor.swift), `ReviewCardState`. Guard: NameClashTests.
- Records conform to `StudyRecord` (Unix-second REAL dates). Dates `.storageRounded` before save (SystemNow rounds). In SQL NEVER bind a bare Date: use `date.databaseUnixSeconds` (ADR-0012).
- IDs: canonical uppercase `UUID().uuidString`; FileStore rejects others. Stored originals use `FileType.storedFileExtension` ("pdf"/"md"), never source pathExtension (T29). Markdown images: `images/<16 hex of sha256(source)>.<ext>` via `MarkdownImageNaming` (ADR-0016).
- Writes: updates = fetch + `record.update(db, columns: [...])` (column-limited, avoids FTS `UPDATE OF` triggers); upsert only `upsertAndFetch(db, onConflict: [PK])`; dedupe = lookup then insert; never REPLACE/INSERT OR IGNORE; `RepositoryError.notFound` for missing rows.
- Migrations (ADR-0013): v1, v2 frozen. Phase 1 has NO schema change; next schema change = dedicated `v3` task (golden + V1FixtureDatabase upgrade test + registeredMigrationsInOrder). L5/L6 shipped as T32 without migration (refuse superseded library in `AppDatabase.init`).
- FTS (v2+): tokenizer `studyreader`, English-only (ADR-0014; file renamed by T30 to 0014-search-tokenizer-english.md). Registered after the sqlite_master probe in prepareDatabase. Hand-written triggers; never synchronize(withTable:). Search: SearchQueryParser quotes everything; highlight hits use FTS column filter `{text editedText} : (expr)`, notes `note : (expr)`; snippets `**`.
- Every test writing indexed tables ends with `FTSIntegrity.check(db)`. Temp stores: `defer { TestFileStore.remove(store) }`; settings: `TestSettings.make()/remove`.
- DI: `AppEnvironment` (Sendable struct) holds FileStore, database, now, settingsStore, sleeper, repositories, services (actors). Tests never call `live()`. Test-host signals: XCTest env, STUDYREADER_IN_MEMORY/-StudyReaderInMemory, injected XCTest dylib, and (T31) XCODE_RUNNING_FOR_PREVIEWS=1.
- Settings (ADR-0015): UserDefaults via `SettingsStore` (keys `settings.*`); live = .standard, in-memory = suite `com.ryanvafaei.StudyReader.Ephemeral`. `AppSettings` (@MainActor @Observable) single instance in `AppSession`, created by AppLaunchModel on ready. No @AppStorage. Waiting only through injected `Sleeper`; `Debouncer` actor.
- Reader (ADR-0017, user decision Q2): documents are NATIVE macOS window tabs in the main window's tab group (library first tab; `ReaderTabbing` sets tabbingMode .preferred + tabbingIdentifier "StudyReaderMain"; never a custom tab bar, BLOCKED instead); technically each is a `WindowGroup(id: "reader", for: String.self)` window, `ReaderRouter` with `ReaderLocation` (.page/.highlight/.searchHit/.documentNote), one `ReaderModel` per window bridges AppKit engines and SwiftUI; commands via FocusedValue (`ReaderActions`, `LibraryActions`); one command per shortcut.
- Export (ADR-0018): `HTTPClient` + `GoogleAuthProviding` protocols; `ExportStatus` values never/ok/queued/failed/docMissing/signInRequired. Signing done by the USER 2026-10-24 (ADR-0011 amended): DEVELOPMENT_TEAM "597KGSTZWJ", no CODE_SIGN_IDENTITY override, keychain-access-groups ["$(AppIdentifierPrefix)com.ryanvafaei.StudyReader"], scripts pass -allowProvisioningUpdates; all builds team-signed; no task touches signing. Google credentials in Secrets/Google.xcconfig (never read); specs use GOOGLE_CLIENT_ID/GOOGLE_REVERSED_CLIENT_ID build settings + Info.plist GIDClientID; empty → "Google export not configured".
- Encrypted PDFs (ADR-0016 amendment, T39): stored copy = `write(to:withOptions:)` with empty owner/user passwords; opens without prompt, keeps outline/metadata, but isEncrypted stays true. Never claim "decrypted/unencrypted". Alternative (rebuild from pages, loses outline) only if the user asks.
- Errors: opening the library throws `AppDatabaseError`; UI never shows raw DatabaseError.
- Test layout: StudyReaderTests/{AppTests,CoreTests,SupportTests,Support,Fixtures} + `<Feature>Tests/`. Fixtures via Bundle(for:) subdirectory "Fixtures/<kind>" (golden exports in Fixtures/golden/export).
- Bug-hunt policy: fix tasks only for critical/high and mediums that get more expensive later; rest to docs/bugs/backlog.md.
- Review (ADR-0021/0022, Phase 2): only Features/Review/Scheduling/ReviewScheduler.swift imports FSRS; stored JSON = our StoredFSRSCard/StoredFSRSLog (Core/Models), ReviewRating raw 1–4; weights = library default params (21). Suspension written only by ReviewSuspension.recompute using FrequencyPolicy.suspendedReason (mastery > override off=user > category off=frequencyOff). introducedAt at first rating. Cloze text snapshot in reviewCard.answer, ranges UTF-16 (ClozeRange). Review day starts 04:00 (ReviewDay, Core/Support). Daily limits are per-review-day budgets; sessions held in memory (AppSession.dailyReviewModel()). Review keys only via focused card .onKeyPress, never .keyboardShortcut without modifiers. Repos split value types + static SQL enum (ReviewQueueSQL, FlashcardSQL) like HighlightBrowseSQL; repository `writer` stays private. No v3 in Phase 2.
- Tests that change settings use TestSettings.make() with AppEnvironment(fileStore:database:now:settingsStore:), never the shared ephemeral suite.
- UI-test tasks are separate (Phase 1 T88/T89, Phase 2 T112/T128) and may run targeted classes; feature tasks only add accessibility identifiers. Every main-window text field spec carries the HANDOFF Return/Escape "Constraint" note naming the UI test that proves it.
- Per-task model overrides go in the spec header `**Model / effort:**` and the README Agent column. Task IDs are global and continue across phases (Phase 1 = T29–T74).

**Why:** keeps Haiku implementers away from name ambiguity, GRDB pitfalls and silent schema drift on the user's real library.
**How to apply:** reuse these exact names and rules in Phase 2+ specs; extend existing repositories/AppEnvironment/AppSession rather than creating parallel types. Related: [[phase-status]].
